# Azure Secure Score Assessment

## Overview

Microsoft Secure Score is a security posture measurement provided by Microsoft Defender for Cloud. It evaluates Azure resources against Microsoft's recommended security best practices and provides a numerical score that helps organizations understand their overall cloud security posture.

Rather than functioning as a compliance certification, Secure Score is a prioritization tool. It helps security teams identify opportunities to reduce risk by implementing recommended security controls across Azure resources.

During this project, I used Secure Score to evaluate my Azure environment, identify areas for improvement, and prioritize security recommendations based on their potential impact.


# Objectives

The objectives of this phase were to:

- Review the Azure Secure Score.
- Understand how Microsoft evaluates cloud security posture.
- Analyze security recommendations.
- Prioritize remediation activities.
- Monitor how security improvements affected the overall score.
- Understand Secure Score from an operational security perspective.

# What is Secure Score?

Secure Score measures how well an Azure environment aligns with Microsoft's recommended security controls.

Microsoft Defender for Cloud continuously evaluates Azure resources and assigns points based on implemented security controls.

Examples of evaluated controls include:

- Identity protection
- Network security
- Resource protection
- Data security
- Monitoring and logging
- Regulatory compliance
- Security configuration

Each implemented control contributes toward the overall Secure Score.

# How Secure Score Works

Microsoft Defender for Cloud continuously performs security assessments on Azure resources.

The process includes:

1. Discover Azure resources.
2. Evaluate resource configurations.
3. Compare configurations against Microsoft's Cloud Security Benchmark.
4. Generate security recommendations.
5. Assign scores to implemented controls.
6. Calculate the overall Secure Score.
7. Reassess the environment after configuration changes.

Because assessments are continuous, Secure Score changes over time as resources are added, removed, or reconfigured.

# Understanding Score Changes

One observation I made during the project was that the Secure Score changed as Microsoft Defender for Cloud reassessed the environment.

For example, after implementing diagnostic logging and other security improvements, the score did not update immediately.

This reinforced an important concept:

**Secure Score is dynamic.**

Microsoft Defender for Cloud periodically reassesses Azure resources, meaning improvements may take some time before they are reflected in the dashboard.

Similarly, the score may decrease when:

- New Azure resources are deployed.
- Additional security recommendations are introduced.
- Microsoft releases new security controls.
- Existing configurations change.

Understanding this behavior is important because Secure Score should be interpreted as a continuous measurement rather than a one-time achievement.

# Prioritizing Recommendations

One of the most valuable aspects of Secure Score is its ability to help prioritize security work.

Rather than attempting to implement every recommendation immediately, I evaluated each recommendation based on:

- Security impact
- Business relevance
- Resource dependencies
- Licensing requirements
- Implementation complexity

This allowed me to focus on security improvements that provided meaningful value while documenting premium or environment-specific recommendations for future implementation.

# Secure Score vs Compliance

Although Secure Score and Regulatory Compliance are closely related, they serve different purposes.

| Secure Score | Regulatory Compliance |
|--------------|----------------------|
| Measures overall security posture | Measures alignment with compliance frameworks |
| Dynamic and risk-based | Framework and control-based |
| Prioritizes security improvements | Evaluates regulatory requirements |
| Changes as recommendations are implemented | Maps Azure resources to security standards |

Understanding this distinction helped me appreciate how organizations use both tools together to manage cloud security.


# Lessons Learned

This exercise changed the way I think about cloud security.

Initially, I assumed that achieving the highest possible Secure Score should be the primary objective.

However, I learned that security engineers should not pursue a perfect score without considering business requirements.

Some recommendations require premium Microsoft Defender plans, additional Azure services, or architectural changes that may not be appropriate for every environment.

Instead, Secure Score should be used to:

- Identify risks.
- Prioritize remediation.
- Track improvements.
- Support security decision-making.
- Continuously monitor cloud security posture.
